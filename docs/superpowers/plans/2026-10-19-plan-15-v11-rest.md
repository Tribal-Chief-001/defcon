# The rest of v1.1: exports, sharing, evidence, displacement, South Asia, watchlist (Plan 15)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native, TDD, one fresh Sonnet reviewer at the end).

**Goal:** finish the items of `docs/BRAINSTORM-v1.1.md` section 4 that were not built: open exports (static data you can download and reuse), moment permalinks and a share button, the evidence trail on an event card, a human-cost layer from UNHCR, a South Asia lens, and a watchlist with alerts. Every item is small, local to the browser or built at build time, and honest about what it is.

**Architecture:** no server. Exports are generated in the browser from the already loaded JSON (CSV with formula-injection protection) and the static JSON files are documented as the open API (`docs/OPEN-DATA.md`). Permalinks extend the hash grammar (`&t=` for the playhead). The evidence trail reads `signals.json` (Plan 14) and the event's own attributes. UNHCR figures are built by hand into a small committed file (`npm run data:displacement`, CC BY 4.0, attribution and the terms link as UNHCR requires). The South Asia lens is a filter over data already loaded. The watchlist lives in `localStorage` and compares the live snapshot with what the user last saw; notifications only after an explicit click.

**Spec:** `docs/BRAINSTORM-v1.1.md` section 4, `docs/LICENCE-CHECK-v1.1.md` (UNHCR terms, read 2026-10-19), D-062.

## Global Constraints
- No regression: all existing tests stay green; budgets hold (lazy chunks for anything big); the India-official map rules are untouched (the lens never draws or labels borders).
- No account, no secret, no tracking: `localStorage` holds only the watchlist and its last-seen times and is wrapped in try/catch; nothing is sent anywhere.
- CSV cells that start with `=`, `+`, `-`, `@`, tab or carriage return are neutralised (spreadsheet formula injection) and quotes are escaped.
- UNHCR: attribution "UNHCR Refugee Population Statistics Database", a link to the Terms of Use for Datasets, no implied endorsement; figures shown with their year and as "not reported" when UNHCR suppresses them, never as 0.
- Alerts say "new events in the data", never "attack" or "will"; notifications are off until the user clicks.

## Review Focus
1. A shared link that opens the wrong thing or crashes the app: malformed `t`, a `t` in the future, a `t` older than the 365-day archive, `#c=XXX&t=...`, `#war=...&t=...`, hostile characters.
2. CSV: a conflict name or place starting with `=` or `@`; commas, quotes and newlines in fields; the BOM for spreadsheets; file names from data.
3. UNHCR numbers shown as 0 when they are suppressed (`"-"`); IDPs counted twice; country-code mismatches (ISO3 of UNHCR against our ids, territories); the figure year.
4. The watchlist: first visit (no last-seen) must not announce everything as new; storage full or blocked; a country removed while an alert shows; a huge list.
5. The evidence trail never implies corroboration where there is none, and says when an event is older than the signal windows.
